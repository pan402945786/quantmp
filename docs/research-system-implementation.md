## 阶段 A：账务基线修复（2026-11-10）

引擎版本更新为 `research-system-0.2.0`。策略配置和既有数据库结构保持兼容，版本进入实验 ID，因此新的诊断结果与旧 `0.1.0` 记录分开保存。

- 目标金额按扣费后权益计算，联立求解 `扣费后权益 + 费率 × 实际净成交额 = 成交前权益`。按交易方向求解分段线性方程，现金预算直接由扣费后权益分配，不通过借款支付手续费。
- 买卖两侧均按实际成交名义金额扣费；全仓买入、换仓、清仓和保留现金共用同一套账务。组合行中的资产权重以扣费后权益为分母，单资产上限约束成交后的仓位；下一次成交前价格变动仍可能使持仓比例漂移。
- 在首个决策日保存初始全现金权益点，首次费用纳入收益、回撤和波动统计；年化区间从该点计算。单个日收益样本的样本波动率记为零。

- 实验以事务追加写入，不再删除或替换历史。相同实验 ID 的元数据及结果一致时不修改任何记录或创建时间，冲突则报错；写入中途失败全部回滚。输入文件移动且内容未变时可幂等保存，保留首次来源路径。该保证适用于保存接口，尚无失败实验或成熟反馈事件的专门表。

## 阶段 B：历史时钟与访问隔离（2026-11-10）

引擎版本为 `research-system-0.3.0`，执行协议为 `daily-close-next-close-v1`。四个原有策略统一通过回放器运行，策略接口从完整 `PricePanel` 改为只读 `HistoryView`。

- 回放器独占完整数据，按 UTC 单向推进。快照只保存已释放行的不可修改副本及时间元数据，不引用回放器或完整面板；无完整文件路径、完整哈希、未来行数或未来资产目录。摘要仅累计已释放价格及可用时间，同一历史前缀产生相同摘要。策略参数也只提供只读的策略配置，不传入终点或全量数据元信息。
- 日期 D 的日线事件时间为 D+1 日 UTC 零点，可用时间为事件时间加 `data_delay_seconds`。尚未到可用时间的行不在快照中，`price()`、`timing()` 越界会抛出 `UnavailableDataError`。现有 CSV 没有实际发布时间、采集时间或修订历史，对应 `BarTiming` 字段为 `None`，可用时间属于声明的协议假设。
- 每次释放先执行此前冻结的目标，再记权益、生成新信号并冻结下一根收盘的目标。订单提交必须早于执行收盘；有发布延迟时，`event_at` 记录假设成交时间，`processed_at` 记录释放价格后处理成交的时间。首版延迟限定为 `[0, 86400)` 秒，保证在下一根收盘前能提交目标。
- 支持配置 `start_at`、`end_at` 及 CLI `--start`、`--end`，均要求带时区并按释放时刻包含边界。首个符合预热与起点条件的释放事件作为运行起点，先前数据仅用于预热。终点之后不再释放数据或成交；只使用最后已处理事件的状态，最终目标追加为 `pending`，不清仓、不补读区间外价格。只有一个决策点的历史也能运行。
- 原有五张表保持结构与内容，额外创建 `decision_audit` 和 `order_events`。前者保存决策时间、可见摘要、可见日期数、最新可用时间及协议；后者追加提交、成交、待定事件。`portfolio_daily.date` 仍为价格标记日，实际组合时钟可按同日关联 `decision_audit.decision_at`；内存组合行直接包含 `as_of`。这两类新增日志同样参加幂等冲突检查和事务回滚。

## 阶段 D：成熟反馈、内部验证与动态选择器（2026-11-10）

引擎版本为 `research-system-0.5.0`，选择器规则为 `purged-regime-mean-v1`。一次回放运行四个独立影子账、一个固定组合 `benchmark` 及一个动态组合 `portfolio`；沿用相同资金、成本、资产上限、时钟和净订单协议。固定对照不受选择器训练和版本状态影响。

### 反馈与时间边界

- 每个决策日 D 为所有影子策略登记预测，执行日为 D+1，H 日期限结束日为 D+1+H。先冻结 `feedback_created`，等结束日价格已可用且组合记账完成后才追加 `feedback_matured`，不修改预测。结束时只保留尚待定记录，不读取后续价格。
- 标签为 `结束日影子扣费后权益 / 执行日影子扣费前权益 - 1`，包含入场执行、区间内和结束日的实际影子调仓费用。它反映持续运行策略的 H 日收益，不是固定一笔持仓的收益，也未额外假设结束日强制卖出；不能直接用来计算实际动态组合净值。
- `FeedbackBook` 由模拟器持有待定标签和入场基数，研究模块仅收到不可修改的 `FeedbackView` 和 `MatureFeedback`。未结束／未可用标签不能进入视图；反馈目录及版本目录不能自行把时钟前推。起点之前仅预热价格，不补跑或回填反馈。

### 训练、验证与生效协议

- 示例候选固定为动量和跌幅回归，现金为回退；不新增底层策略或搜索参数。状态取当前可见资产回看收益均值的正负，得到 `up`／`down_or_flat`，状态在标签登记时冻结。
- 每 30 天研究一次，使用此前 180 天训练及最近 60 天验证，期限为 5 天。训练样本的决策和成熟时点都需满足训练切分；跨入验证期才成熟的训练标签剔除。验证样本从验证期开始决策，且必须在当前时点已成熟。
- 所有研究样本按固定日历规则 `decision_date.toordinal() % (H+1) == 0` 抽取。每个候选相邻样本的执行／结束区间互不重叠；同时保留同日跨策略比较，不能把策略数当作独立时间证据量。
- 训练阶段估计各状态／策略的 `平均净收益 - uncertainty_penalty × 样本标准差 / sqrt(n)`，默认惩罚为 1。每个候选至少 12 个训练样本；状态内不足 6 个时退回该候选的训练期总体估计。选择得分最高且为正的候选，非正则留现金，得分相同按名称排序。该惩罚分数是启发式研究指标，不宣称统计置信区间或有效显著性检验。
- 验证不重新拟合或挑选验证期赢家，只评价训练形成的状态策略。至少要求 6 个验证期样本，其中至少 3 个实际选用非现金策略，代理得分仍须为正。样本不足时登记研究拒绝并保留现有版本（尚无版本则现金）；验证失败时保留失败证据，并冻结全现金回退版本。
- 研究回调视为同一离散时点完成，记录创建、训练完成和冻结时间，默认 1 天后生效。未到生效时间的版本不能出现在可用目录或参与预算决策。当天先处理旧订单和成熟反馈，再激活已到期版本、研究并冻结新版本；新版本最早用于下一次符合生效条件的决策，而新订单仍需等下一根收盘执行。
- 当前默认策略预算为 100%，按已生效版本和当前状态分给一个候选；现金及底层策略未使用的仓位继续留现金。预算、状态、版本、证据截止及理由保存到 `allocation_decisions`。版本和研究切换不替换资金账，继承旧持仓并按延迟协议退出及计费。

### 冻结、恢复与追加规则

- `replay.py start` 在任何决策前保存解析后的完整配置、策略目录、执行／选择／研究规则、真实 UTC 创建时间、九个运行源码的 SHA-256、Python 版本／平台信息、初始资产池、数据语义指纹及原始文件来源。源码摘要规范化 CRLF 为 LF，避免 Git 换行转换改变标识；普通 `research.py` 的实验 ID 也新增源码摘要。
- 支持 `standalone`、`portfolio`、`selector`、`research` 四种模式，默认研究模式。`--until` 是运行暂停点，不更改冻结协议中的 `start_at`／`end_at`，时间必须含时区，实际释放不能超过当前真实 UTC 时钟。
- 每个完整事件处理后可捕获现金、单位持仓、目标订单、成交和预测账、成熟／待定反馈、选择器版本／下次研究时点、候选状态、尝试预算及已有日志。JSON 采用固定类型白名单，不使用 pickle、eval 或任意类加载；只包含已消费状态和未来已计划的事件，不序列化原始完整价格面板。
- 恢复时直接还原这些状态，只重新建立已释放的价格视图及其摘要，再跳过已经处理的日期。候选的活动目录与其状态登记册重建为同一对象关联，防止确认或待退出状态在重启后分离。不会通过重算过去策略、重置权益或拼接多个独立回测恢复资金。
- 校验检查点和清单摘要、实际源码、严格 Python 环境、参数、资产池与先前已知的全部价格。初始文件中虽尚未回放但已知的行同样受保护。只能在相同资产池后追加连续完整日线；修订旧价格、截断旧文件、改参数、换代码或回退时钟均拒绝。新增数据的新路径保存在修订中，之后可按该路径续跑。
- 没有新事件／数据时不生成新状态或追加伪事件。每次真正续跑生成新的检查点哈希并关联父哈希。文件原子发布且不可覆盖；SQLite 新增 `frozen_runs`、`frozen_checkpoints`，每个修订关联独立实验快照。同一父检查点在一个数据库中只能有一条后续分支，冲突或重复保存不能覆盖旧曲线。
- CLI 在检查点旁归档运行源码与文件摘要，旧版本可用该归档和原 Python 环境继续，原价格文件仍需保留。先保存不可覆盖文件，再事务追加数据库修订；两种介质不是统一事务，中断后可以用相同输出幂等补齐。`runs/` 和数据库均不提交 Git。

### 独立审计与报告

- `replay.py report` 只读取检查点和匹配的价格，不调用策略或重新研究。分别重建成交后现金、单位持仓、权益、费用、换手、回撤和净收益，核对下一根收盘时序、预算及仓位约束；从影子权益和入场费用重建成熟标签，检查训练／验证切分和版本可用时间。
- 候选审计检查冻结、影子开始、确认、生效及退休事件，拒绝回填历史或用尚未成熟／冻结前的影子反馈确认新版本；假设和尝试结果继续在报告保留。审计不通过时 CLI 不把结果作为成功的冻结修订保存。
- 报告输出不可覆盖的 Markdown、JSON、连续权益 CSV。JSON 额外提供逐月净收益、最大水下持续天数、低于初始资金的最长天数、选择切换数、资产及版本的账务贡献。持仓跨区间的市值变化归给此前建立头寸的版本，成交费用归给提交该订单的版本；这是账务归属，不是反事实研究增量。

## 时间和成交口径

策略使用日期 `t` 的日线收盘数据时，历史时钟最早已到 `t+1` 日 UTC 零点（另加配置的可用时间延迟），新目标在价格标记为 `t+1` 的日线收盘执行，即 `t+2` 日 UTC 零点。新目标不能按刚刚释放的价格成交。交易成本按换手名义金额乘以 `transaction_cost_bps / 10000` 扣除，目标金额按扣费后权益预留费用。首版仍未建模盘口冲击、部分成交或最小交易单位。

当前指标包括期末权益、总收益、年化收益、年化波动率、最大回撤、累计换手和再平衡次数。演示数据很短，年化结果只能用于验证计算链路，不能用于判断真实市场策略有效性。
