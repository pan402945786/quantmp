# 研究系统阶段 1 实现记录

更新时间：2026-11-10

本文件记录 `research-system-design.md` 阶段 1 原型及后续阶段 A、B 的实际代码交付。当前实现是本地、离线、确定性的固定策略历史回放，使用 CSV 收盘价数据，不连接交易所，也不执行真实下单。

后续开发依据 [历史时钟驱动的策略组合研究与模拟实盘](strategy-selection-replay.md)。当前入口已实现历史时钟和数据访问隔离，策略组合选择和持续改进闭环仍待实现。

## 已实现

- `research_system.py`：价格面板加载与校验、数据哈希、动量候选、相对偏离回归候选、等权基准、现金基准、目标仓位、单根数据延迟、换手成本、最大仓位限制、回测指标和 SQLite 记录。
- `research.py`：统一命令行入口，支持单策略或全部策略运行，并输出文本或 JSON 结果。
- `historical_replay.py`：UTC 时钟、按可用时间释放的只读快照、可见前缀摘要、日线时间元数据及冻结的延迟目标。
- `data/demo_prices.csv`：固定的三资产演示数据，包含趋势、反转和横盘阶段。
- `research_config.json`：第一轮实验配置，包括初始资金、5 日回看窗口、60% 单资产上限和 10 bps 交易成本。
- `test_research_system.py`：覆盖数据校验、确定性哈希、延迟日期、策略入口、资金守恒、扣费后仓位、指标算例及不可覆盖保存。
- `test_historical_replay.py`：覆盖时区和发布时间边界、只读快照、未来信息隔离、前缀不变性、订单时序、区间终止、审计保存和 CLI。标签成熟的实现与测试待后续阶段交付。

## 阶段 A：账务基线修复（2026-11-10）

引擎版本更新为 `research-system-0.2.0`。策略配置和既有数据库结构保持兼容，版本进入实验 ID，因此新的诊断结果与旧 `0.1.0` 记录分开保存。

- 目标金额按扣费后权益计算，联立求解 `扣费后权益 + 费率 × 实际净成交额 = 成交前权益`。按交易方向求解分段线性方程，现金预算直接由扣费后权益分配，不通过借款支付手续费。
- 买卖两侧均按实际成交名义金额扣费；全仓买入、换仓、清仓和保留现金共用同一套账务。组合行中的资产权重以扣费后权益为分母，单资产上限约束成交后的仓位；下一次成交前价格变动仍可能使持仓比例漂移。
- 在首个决策日保存初始全现金权益点，首次费用纳入收益、回撤和波动统计；年化区间从该点计算。单个日收益样本的样本波动率记为零。
- 要求回测日期连续且为日频，缺日明确拒绝，不填价格，以保证按 365 日年化的收益观测口径一致。费率限定为 `[0, 10000)` bps，拒绝未知资产、非有限或负权重及超出总预算的目标。
- 实验以事务追加写入，不再删除或替换历史。相同实验 ID 的元数据及结果一致时不修改任何记录或创建时间，冲突则报错；写入中途失败全部回滚。输入文件移动且内容未变时可幂等保存，保留首次来源路径。该保证适用于保存接口，尚无失败实验或成熟反馈事件的专门表。

阶段 A 当轮验证：`python -m unittest -v` 共 26 项通过，包含资金守恒、买卖费用、扣费后权重、初始指标算例、极端资金尺度与费率、无需交易、250 次固定种子的价格／预算／成本转换、幂等保存、冲突拒绝与事务回滚，以及原有价差工具和下载器测试。

## 阶段 B：历史时钟与访问隔离（2026-11-10）

引擎版本为 `research-system-0.3.0`，执行协议为 `daily-close-next-close-v1`。四个原有策略统一通过回放器运行，策略接口从完整 `PricePanel` 改为只读 `HistoryView`。

- 回放器独占完整数据，按 UTC 单向推进。快照只保存已释放行的不可修改副本及时间元数据，不引用回放器或完整面板；无完整文件路径、完整哈希、未来行数或未来资产目录。摘要仅累计已释放价格及可用时间，同一历史前缀产生相同摘要。策略参数也只提供只读的策略配置，不传入终点或全量数据元信息。
- 日期 D 的日线事件时间为 D+1 日 UTC 零点，可用时间为事件时间加 `data_delay_seconds`。尚未到可用时间的行不在快照中，`price()`、`timing()` 越界会抛出 `UnavailableDataError`。现有 CSV 没有实际发布时间、采集时间或修订历史，对应 `BarTiming` 字段为 `None`，可用时间属于声明的协议假设。
- 每次释放先执行此前冻结的目标，再记权益、生成新信号并冻结下一根收盘的目标。订单提交必须早于执行收盘；有发布延迟时，`event_at` 记录假设成交时间，`processed_at` 记录释放价格后处理成交的时间。首版延迟限定为 `[0, 86400)` 秒，保证在下一根收盘前能提交目标。
- 支持配置 `start_at`、`end_at` 及 CLI `--start`、`--end`，均要求带时区并按释放时刻包含边界。首个符合预热与起点条件的释放事件作为运行起点，先前数据仅用于预热。终点之后不再释放数据或成交；只使用最后已处理事件的状态，最终目标追加为 `pending`，不清仓、不补读区间外价格。只有一个决策点的历史也能运行。
- 原有五张表保持结构与内容，额外创建 `decision_audit` 和 `order_events`。前者保存决策时间、可见摘要、可见日期数、最新可用时间及协议；后者追加提交、成交、待定事件。`portfolio_daily.date` 仍为价格标记日，实际组合时钟可按同日关联 `decision_audit.decision_at`；内存组合行直接包含 `as_of`。这两类新增日志同样参加幂等冲突检查和事务回滚。

本轮 `python -m unittest -v` 共 39 项通过。新增 13 项覆盖边界时刻、时区转换、时间倒退拒绝、快照不可修改且不会随回放增长、未来文件摘要与资产目录隔离、修改／追加／截断未来保持决策前缀一致、单点终止、订单冻结与延迟成交、起止区间、审计冲突与最后一张表写入失败回滚，以及 CLI。

当前 BTC/SOL 文件完整回放实验 ID 为 `8f52d0a6fc8d4d10`：每个策略保存 2,133 个权益点、2,133 次决策及 1 个待执行目标。以价格标记日 2022-12-31 为核验边界，分别修改后续价格、追加一天、截断后续数据，四个策略此前的信号、目标、快照摘要、成交、权益与已发生订单事件完全一致。再次逐日重建账务，最大绝对误差为 `1.31e-7`，现金非负且成交后仓位符合上限。数据库原有 2 个实验的全部旧表记录未变，新实验重复执行后全库内容不变。

该隔离是程序接口和数据所有权边界，不是针对可任意读取文件或检查进程内存代码的安全沙箱。当前尚无训练器、成熟标签反馈、策略版本生效目录、影子组合、选择器或研究改进流程；这些能力不能由本阶段测试推断为已经完成。

## 时间和成交口径

策略使用日期 `t` 的日线收盘数据时，历史时钟最早已到 `t+1` 日 UTC 零点（另加配置的可用时间延迟），新目标在价格标记为 `t+1` 的日线收盘执行，即 `t+2` 日 UTC 零点。新目标不能按刚刚释放的价格成交。交易成本按换手名义金额乘以 `transaction_cost_bps / 10000` 扣除，目标金额按扣费后权益预留费用。首版仍未建模盘口冲击、部分成交或最小交易单位。

当前指标包括期末权益、总收益、年化收益、年化波动率、最大回撤、累计换手和再平衡次数。演示数据很短，年化结果只能用于验证计算链路，不能用于判断真实市场策略有效性。

## 运行

```powershell
python research.py
python research.py --strategy momentum --json
python research.py --start 2022-01-01T00:00:00Z --end 2022-02-01T00:00:00Z --data-delay-seconds 60 --json
python research.py --data data/demo_prices.csv --config research_config.json --database research.sqlite3
python -m unittest -v
```

默认会把实验写入 `research.sqlite3`。该文件被 `.gitignore` 忽略，实验可以通过原有五张表以及 `decision_audit`、`order_events` 追溯。实验 ID 由代码版本、输入数据哈希、配置和策略列表共同计算；相同输入会得到相同 ID 和相同结果。全量哈希只用于运行元数据，不传给策略。

## 当前边界

阶段 1 已接入 Binance 公共现货日线数据，当前数据文件包含 `BTCUSDT` 和 `SOLUSDT`，区间为 2021-01-01 至 2026-11-08，共 4,276 行。下载入口是 `download_history.py`，数据清单保存在 `data/btc_sol_daily.manifest.json`，其中记录来源和 SHA-256。下载器会排除当前 UTC 日尚未收盘的 K 线。缺失价格不会被填充，数据必须是完整的日期 × 资产矩形面板。

当前仍未接入基本面指标、复杂市场状态模型、参数搜索、候选版本替换或真实交易。`relative_reversion` 当前按资产自身历史跌幅分配权重，未剔除市场因素。阶段 A、B 已完成；下一步从阶段 C 推进：连续固定组合 → 选择器 → 研究改进 → 冻结后确认。
