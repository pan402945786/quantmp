# 研究系统阶段 1 实现记录

更新时间：2026-11-10

本文件记录 `research-system-design.md` 阶段 1 的实际代码交付。当前实现是本地、离线、确定性的静态回测原型，使用 CSV 收盘价数据，不连接交易所，也不执行真实下单。

后续开发依据 [历史时钟驱动的策略组合研究与模拟实盘](strategy-selection-replay.md)。当前入口属于静态回测原型，尚未实现用户确认的时间隔离、策略组合选择和持续改进闭环。

## 已实现

- `research_system.py`：价格面板加载与校验、数据哈希、动量候选、相对偏离回归候选、等权基准、现金基准、目标仓位、单根数据延迟、换手成本、最大仓位限制、回测指标和 SQLite 记录。
- `research.py`：统一命令行入口，支持单策略或全部策略运行，并输出文本或 JSON 结果。
- `data/demo_prices.csv`：固定的三资产演示数据，包含趋势、反转和横盘阶段。
- `research_config.json`：第一轮实验配置，包括初始资金、5 日回看窗口、60% 单资产上限和 10 bps 交易成本。
- `test_research_system.py`：覆盖数据校验、确定性哈希、延迟日期、策略入口、资金守恒、扣费后仓位、指标算例及不可覆盖保存；未来隔离与标签成熟的测试待相关阶段实现。

## 阶段 A：账务基线修复（2026-11-10）

引擎版本更新为 `research-system-0.2.0`。策略配置和既有数据库结构保持兼容，版本进入实验 ID，因此新的诊断结果与旧 `0.1.0` 记录分开保存。

- 目标金额按扣费后权益计算，联立求解 `扣费后权益 + 费率 × 实际净成交额 = 成交前权益`。按交易方向求解分段线性方程，现金预算直接由扣费后权益分配，不通过借款支付手续费。
- 买卖两侧均按实际成交名义金额扣费；全仓买入、换仓、清仓和保留现金共用同一套账务。组合行中的资产权重以扣费后权益为分母，单资产上限约束成交后的仓位；下一次成交前价格变动仍可能使持仓比例漂移。
- 在首个决策日保存初始全现金权益点，首次费用纳入收益、回撤和波动统计；年化区间从该点计算。单个日收益样本的样本波动率记为零。
- 要求回测日期连续且为日频，缺日明确拒绝，不填价格，以保证按 365 日年化的收益观测口径一致。费率限定为 `[0, 10000)` bps，拒绝未知资产、非有限或负权重及超出总预算的目标。
- 实验以事务追加写入，不再删除或替换历史。相同实验 ID 的元数据及结果一致时不修改任何记录或创建时间，冲突则报错；写入中途失败全部回滚。输入文件移动且内容未变时可幂等保存，保留首次来源路径。该保证适用于保存接口，尚无失败实验或成熟反馈事件的专门表。

本轮验证：`python -m unittest -v` 共 26 项通过，包含资金守恒、买卖费用、扣费后权重、初始指标算例、极端资金尺度与费率、无需交易、250 次固定种子的价格／预算／成本转换、幂等保存、冲突拒绝与事务回滚，以及原有价差工具和下载器测试。

## 时间和成交口径

策略在日期 `t` 使用截至该日的收盘价计算信号，在日期 `t+1` 的收盘价执行目标仓位。历史数据中没有日内成交信息，因此不会把 `t` 的信号直接按 `t` 的价格成交。交易成本按换手名义金额乘以 `transaction_cost_bps / 10000` 扣除，目标金额按扣费后权益预留费用。首版仍未建模盘口冲击、部分成交或最小交易单位。

当前指标包括期末权益、总收益、年化收益、年化波动率、最大回撤、累计换手和再平衡次数。演示数据很短，年化结果只能用于验证计算链路，不能用于判断真实市场策略有效性。

## 运行

```powershell
python research.py
python research.py --strategy momentum --json
python research.py --data data/demo_prices.csv --config research_config.json --database research.sqlite3
python -m unittest -v
```

默认会把实验写入 `research.sqlite3`。该文件被 `.gitignore` 忽略，实验可以通过 `experiments`、`predictions`、`trades`、`portfolio_daily` 和 `metrics` 表追溯。实验 ID 由代码版本、输入数据哈希、配置和策略列表共同计算；相同输入会得到相同 ID 和相同结果。

## 当前边界

阶段 1 已接入 Binance 公共现货日线数据，当前数据文件包含 `BTCUSDT` 和 `SOLUSDT`，区间为 2021-01-01 至 2026-11-08，共 4,276 行。下载入口是 `download_history.py`，数据清单保存在 `data/btc_sol_daily.manifest.json`，其中记录来源和 SHA-256。下载器会排除当前 UTC 日尚未收盘的 K 线。缺失价格不会被填充，数据必须是完整的日期 × 资产矩形面板。

当前仍未接入基本面指标、复杂市场状态模型、参数搜索、候选版本替换或真实交易。`relative_reversion` 当前按资产自身历史跌幅分配权重，未剔除市场因素。阶段 A 账务修复已完成；下一步从阶段 B 推进：历史时钟与访问隔离 → 连续固定组合 → 选择器 → 研究改进 → 冻结后确认。

## 已知问题与待实现能力

- 策略收到完整价格面板，尚无强制的历史时钟访问边界。
- 尚无成熟标签约束、可训练组合选择器、新策略生效管理、连续资金账的版本切换或研究改进循环。
- 不可覆盖的静态实验保存已实现；失败研究尝试、成熟反馈与版本事件的追加日志仍待后续阶段交付。
- 当前可信基线为资产等权和现金；BTC、SOL 各自买入持有及风险预算匹配对照仍需后续补充。

此前全区间回测及本轮账务修复后的重跑均为诊断结果，不构成策略选择能力或持续盈利能力的验证。下一步实现强制的历史时钟与可用时间边界，再进入组合和选择器实验。
