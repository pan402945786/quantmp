# 历史时钟驱动的策略组合研究与模拟实盘

确认日期：2026-11-10。状态：阶段 A 到 E 首版及 F 工程首版已交付，冻结协议、检查点恢复和审计报告已实现；首版仍亏损，两个候选未通过内部验证，真正冻结后数据及独立盈利确认仍待积累。

本文件记录用户最新确认的核心目标与开发方向。后续涉及研究流程、策略选择、组合分配和验证的开发，以本文件为主线；[研究系统设计](research-system-design.md) 提供总体背景，[实现记录](research-system-implementation.md) 记录实际交付。若旧文档的实施顺序与本文件不同，以本文件为准，并同步更新文档。

## 1. 核心目标

系统最终要研究和检验的，是根据当时信息挑选策略组合、在变化的市场中配置资金，以持续积累扣除成本后收益的能力。

持续盈利是待验证的长期目标，不意味着每个交易日、每个月或每个模拟阶段必须盈利。评价需要同时考虑净收益、回撤、亏损持续时间、成本和跨阶段稳定性。具体风险容忍度和成功门槛应在正式实验前配置、冻结，不根据结果倒推。

研究对象分为三个层次：

| 层次 | 要回答的问题 | 评价方式 |
| --- | --- | --- |
| 底层策略库 | 哪些策略具有可解释且可检验的信号？ | 独立影子记录、成熟结果、成本及失效条件 |
| 选择与组合机制 | 此时采用哪些策略、各分配多少资金、是否留现金？ | 与固定策略和固定组合比较，检查动态决策的增量 |
| 研究改进机制 | 何时应改进策略或补充策略库？ | 候选研究记录、验证与生效时间，以及生效后的连续表现 |

最终成绩来自整条连续运行的组合资金曲线与当时决策记录，包括失败选择、调仓费用、空仓期及版本切换影响。

## 2. 用户确认的工作方式

选择历史上的某一天作为模拟当前时间。系统只能访问该时点已经可获得的数据，用这些数据研究策略、验证组合选择规则、决定是否补充策略库，并冻结下一阶段的运行版本。模拟器随后逐步释放未来数据，驱动模拟成交、结果成熟、复盘和下一次研究。

```text
历史时钟 T
  → 截至 T 可用的数据与成熟反馈
  → 研究、验证、选择策略与组合
  → 冻结版本和决策
  → 时间向前推进并释放新数据
  → 模拟成交、计费、更新组合账
  → 结果成熟、复盘
  → 保留、调整或研究新候选
  → 下一次冻结，继续向前
```

示例：把 2022-01-01 00:00 UTC 作为起点，研究只能使用此前已收盘且已可用的数据。2022 年及之后的数据由回放器保存，在对应时刻逐步释放。此日期仅用于说明，尚未指定为正式实验参数。

## 3. 历史时钟和信息边界

### 3.1 程序限制访问范围

模拟器可以持有完整历史，但研究、特征、策略、状态、选择器和候选搜索模块只能获得截至当前研究时钟的数据视图。禁止把完整价格面板传入这些模块后仅靠约定不读取未来行。

首版通过受限接口和独立的数据所有权实现边界，并测试越界访问失败。若以后运行可任意读文件的生成代码，需要额外隔离进程和文件权限；普通 Python 对象封装本身不构成针对任意代码的安全沙箱。

只读历史视图、截至当前时点的快照摘要和版本目录不得暴露未来价格、未来标签、未来样本数或尚未生效的策略。完整数据摘要可由模拟器保存在运行元数据中，不作为选择器的可用特征。

### 3.2 数据时间

记录事件时间、发布时间、采集时间和可用时间。某条数据只有在其可用时间不晚于研究时钟时才能进入决策；历史收盘日不能直接当作当日零点即可使用。

当前 BTC/SOL 文件是 UTC 日线收盘价。标记日期为 D 的价格，最早在 D 日结束后可用；后续如加入发布延迟，按配置进一步延后。尚未收盘的日线不得进入研究或成交参考。

当前 CSV 是事后下载的历史快照，尚无逐次修订存档，不能声称已经还原所有数据的历史发布版本。

### 3.3 标签成熟

尚未结束的持有期收益不进入训练、完整评价或策略替换依据。训练和内部验证按时间切分，训练标签的结束时间及可用时间必须满足各自切分边界，必要时移除跨边界样本或设置间隔。

模拟结束时仍未成熟的标签标为待定；不得补读区间外数据完成评价。

## 4. 研究、冻结与执行顺序

1. 推进时钟，释放此时已可用的市场数据，处理此前已提交且现已到成交时间的订单，并更新账务。
2. 追加已经成熟的反馈，更新底层策略影子记录及实际组合记录。
3. 在预定研究时点，使用当前可见历史做内部训练、验证和候选比较。
4. 冻结候选、选择器、风险规则、成本假设、数据快照和生效时间。
5. 运行当前已生效版本，记录选择理由、策略预算和资产目标，合并净订单并进行风险与资金检查。
6. 按成交协议安排后续执行，然后继续推进时钟。

每天执行策略与定期重新研究是不同节奏。冻结的选择规则可以按照预先定义的状态更新机制动态调权；重新训练、更改参数或增加策略则必须形成新版本，并记录下一生效时间。

首版沿用收盘数据形成信号、下一根日线收盘模拟执行的约定。时间推进中必须明确：当前更新的成交来自之前的订单，新生成的订单不能使用已经发生的收盘价成交。后续更换执行协议时单独版本化。

## 5. 策略选择与组合能力

### 5.1 可用输入

选择器可使用当前可见的趋势、波动、回撤等市场特征，以及各策略已成熟的历史结果、成本、共同风险、稳定性和样本量。特征的标准化、阈值估计和模型拟合也必须在当前可见数据内完成。

现有数据只有 BTC/SOL 收盘价，首版不能假定已有盘口深度、流动性或基本面特征。是否引入机器学习由证据决定；先建立可解释的固定组合和简单动态分配基线。

### 5.2 输出

每次决策输出采用的策略版本、策略资金预算、现金预算、理由与证据范围。策略预算转换为资产目标后统一检查同资产重叠暴露、集中度、总预算、换手和资金可用性；所有目标合并后形成实际净订单。

允许不交易、降低仓位、全部现金、继续观察和保持旧版本。不能因为刚经历亏损就直接提高最近赢家的权重。

### 5.3 连续运行

实际组合在研究切分、模型更新和策略切换时保持现金与持仓连续，不清零资金、不重置净值、不删除失败区间。退出旧策略的头寸必须遵守执行与成本约定。

各底层策略持续生成独立的影子记录，以观察未采用策略的表现。影子资金曲线属于假设模拟，不能直接加总为实际组合收益，也不能假定历史上可以无成本切换。

## 6. 策略库扩充与生效规则

策略库不足的判断，需要能追溯到当前可见证据，例如现有策略共同暴露过大、长期缺少合格候选、特定已观察到的市场条件下反复失效或成本侵蚀。低收益本身不自动意味着必须新增策略。

每个新候选必须记录经济假设、数据要求、主要改动、开发与内部验证范围、尝试预算、失败条件和退出条件。记录全部尝试，包括淘汰版本。

候选可以在创建时可见的过去数据上做研究回测，但这些结果只能作为研究证据；它的历史影子成绩不得补入此前的实际组合曲线。通过预定验证、完成冻结后，最早从记录的生效时间参与后续选择和成交。

研究和实现需要时间，应记录创建、研究完成、冻结和生效时间。首版可以采用预先声明的离散研究周期与生效延迟；不能看到下一阶段收益后，倒填候选创建时间或声称候选早已可用。

大模型或人工若已知道后续事件，不能把这些知识写成历史时点的输入。已有模型的先验知识无法靠口头约定清除；相关候选须标记事后研究性质，依靠冻结后的数据进一步确认。

## 7. 冻结协议、版本和日志

每轮模拟开始前固定并保存以下项目；尚未确定的参数不得伪装成已经验证的最优值：

- 起点、终点、时区、预热长度、可用时间规则、持有与预测期限。
- 资产池及当时可交易资格；当前范围为 BTCUSDT、SOLUSDT，研究结论限于该资产池。
- 研究频率、决策频率、内部训练与验证方式、搜索预算、选择器更新及生效规则。
- 手续费、价差或滑点假设、成交延迟、缺失数据处理和停止规则。
- 单资产、策略预算、总仓位、换手和回撤等风险约束，以及主要评估指标。
- 初始策略库、对照基准、代码摘要、可见数据快照、随机种子和配置。

最小日志包括：

| 记录 | 关键内容 |
| --- | --- |
| 回放运行 | 运行 ID、历史时钟、协议版本、代码摘要、检查点 |
| 研究实验 | 假设、父版本、可见数据截止、切分、全部尝试、结果、采用或放弃理由 |
| 策略与选择器版本 | 创建、训练完成、冻结、生效时间、参数、证据与允许的数据范围 |
| 组合决策 | 决策时点、可见快照、候选集合、采用与拒绝理由、预算和风险检查 |
| 预测与反馈 | 原始预测、期限、成熟时间、待定状态及追加的实际标签 |
| 订单与组合账 | 目标、净订单、成交、拒单、费用、现金、持仓、权益及风险 |

预测、已执行决策和历史版本不可覆盖。成熟标签和复盘以追加事件关联原记录；重新运行是新的运行或幂等复现，不能通过删除旧失败记录宣称成绩改善。

## 8. 评价与对照

所有对照使用相同可见信息、执行时间、资金与成本约定，并明确风险预算的差异：

- 现金、BTC 和 SOL 各自买入持有、资产等权。
- 固定单策略、预先冻结权重的固定策略组合。
- 动态策略选择与组合；必要时增加按当时历史波动确定风险预算的对照。

买入持有与严格仓位上限的组合若风险暴露不同，需要明确标注；额外提供预算匹配的对照。事后全区间最优策略只能列为不可交易的参考上界，不能充当当时可执行的选择器。

报告同时给出连续资金曲线、分期净收益、最大回撤及持续时间、亏损持续时间、波动、换手、成本压力、资产和策略贡献、现金比例、切换次数与各版本生效后的结果。

分别回答：底层策略是否有信号、选择器是否超过固定组合、改进机制是否带来增量。后两个能力不能从某条底层策略的全区间高收益推导出来。

历史回放允许在结果成熟后影响下一轮决策；同一时期一旦用于修改系统设计或选择规则，就不再是该修改的独立测试。程序隔离可以检验因果流程，冻结后的新增数据提供更强的确认。

## 9. 当前实现与已知问题

当前已经具备本地价格面板、四个策略入口、独立影子账、连续固定组合、状态选择器、有限候选研究、成本回放、SQLite 记录、确定性演示数据和 BTC/SOL 下载器。现有四个入口为动量、`relative_reversion`、资产等权与现金，统一通过 UTC 历史时钟和只读可见历史运行；阶段 E 首版只研究预先声明的窗口变体，不包含开放式策略生成。

`relative_reversion` 当前只是依据自身过去跌幅分配权重，尚未剔除市场因素，不应称为已经实现了完整的相对偏离模型。

2026-11-10 阶段 A 已修复此前复核发现的账务问题：

- 满仓目标改为按扣费后权益计算，并预留买卖成本，成交不产生负现金。
- 实际持仓比例按扣费后权益记录，成交后仓位符合配置上限（允许浮点舍入容差）。
- 指标包含首个决策日的初始资金权益点，首次成本进入回撤及波动计算。
- SQLite 改为事务追加：相同结果幂等复现、冲突拒绝覆盖、失败回滚，旧版本实验保留。

阶段 B 已实现的边界：

- `HistoryView` 只包含已到可用时间的数据和前缀摘要，不携带全量面板、文件路径或未来数据目录，越界访问拒绝。
- 日线在次日 UTC 零点加配置延迟后释放；上一笔目标先成交，之后才提交下一根收盘的目标；终止后保留待执行事件。
- 支持按带时区的释放时刻限定运行起止，决策审计与订单事件追加保存，不重写旧实验。

阶段 C 已交付独立影子账与连续固定组合：

- 每个时点各策略仅计算一次，零预算策略也持续记录；独立影子账使用与实际模拟组合相同的初始资金、成本、可见信息和执行时间。
- 事先冻结的策略预算转换为资产目标后合并，抵消反向调仓，费用仅按实际组合净成交额计提，组合资金和持仓持续累计。
- 预算未分配部分及策略自身未使用仓位保留现金；角色、预算、权重贡献、风险检查及理由追加保存，影子收益不加总冒充组合收益。

阶段 D 已交付成熟反馈及有限策略库选择器：

- 影子标签在期限结束且价格已可用后追加成熟结果，只读训练视图不含待定标签，结束时保留未成熟记录。
- 按时间切分训练和验证、剔除跨边界标签、按固定日历抽取不重叠持有期样本；训练状态规则在验证期不重新拟合，代理得分不冒充实际动态收益。
- 每轮选择器记录完整证据、拒绝理由、冻结及延迟生效时间；未到期版本不可被采用。样本不足等待，验证失败形成现金回退版本。实际资金账保持连续，固定组合和影子账作为独立对照。

阶段 E 已交付受限研究与确认流程：

- 根据原选择器持续留现金及足够成熟证据触发，按冻结清单和全局尝试预算研究候选；假设、父版本、证据、失败和预算耗尽事件完整追加。
- 内部训练／验证仅访问当前可见价格，研究收益不回填。通过后冻结，并在之后的日期新增独立候选影子账；确认使用创建后成熟的、与父策略配对的非重叠收益样本。
- 确认通过后延迟生效，只替换原选择器选中的相应父策略位置；确认失败／超时拒绝，生效后按冻结的失效规则延迟退出。实际资金账与原选择器、固定组合对照均连续保留。

阶段 F 工程首版已实现：

- 在决策前冻结实际源码、完整参数、规则、环境和数据指纹；检查点保存真实资金、订单、标签、版本、预算及日志，恢复不重复过去的策略决策。
- 续跑只接受同一资产池追加完整日线，已知价格、代码或参数变更需另起运行；源码与旧检查点保留，修订链拒绝覆盖和静默分支。
- 独立审计输出连续权益、逐月收益、回撤持续期、资产／版本账务贡献及失败结果。只有初始快照外、可用时间晚于真实冻结时间的新行，才进入单独的新增区间，不自动认定盈利有效。

当前 99 项测试及 BTC/SOL 恢复核验见 [实现记录](research-system-implementation.md)。从 2021 年末检查点补入 1,773 天历史，全部结果与完整回放逐项一致。两个候选仍验证失败，实际净收益 -22.39%；没有冻结后新行，报告为 `awaiting_post_freeze_rows`。A 到 F 工程首版不表示已达到持续盈利目标。

示例参数仍是工程假设，全区间回放不能据此宣称系统已经具备持续盈利能力。首版接口隔离不构成任意代码安全沙箱，现有 CSV 的可用时间仍为显式协议假设。

## 11. 必要测试与完成标准

- 修改或追加 T 之后的数据，不改变截至 T 的特征、研究结果、策略候选集合、选择器状态、目标预算和决策理由。
- 未来数据访问被拒绝；全局标准化、标签、数据摘要和版本目录不能绕过边界。
- 相同历史前缀、配置、版本和随机种子，产生相同决策；完整回放与检查点恢复结果一致。
- 新研究版本只在研究完成并达到生效时间后可被选择；新策略不能回填实际组合历史。
- 标签成熟前不用于训练或完整评价；训练标签不跨内部验证边界。
- 成交发生在已提交订单允许的时间；缺失价格和交易失败有明确处理。
- 买卖费用扣减正确，现金不产生隐含借款；扣费后仓位和总预算满足约束。
- 内部研究切分、选择器更新和候选替换不重置实际现金、持仓或净值。
- 多策略目标先合并，实际费用基于净订单；影子收益不冒充实际成交收益。
- 历史预测、决策和失败实验不可覆盖，后续评价只能追加；所有对照采用明确一致的执行与成本规则。
- 原有价差工具测试继续通过；文档中文使用 UTF-8，提交前检查异常问号和替换字符。

验收不是某个历史参数取得最高收益，而是上述约束成立，并能据此审计策略选择与组合机制的实际增量。
